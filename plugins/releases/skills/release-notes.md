# When to use
Writing "What's new" for a release.

# How
1. Call list_releases for the project, then list_work with the field `releases.release:<release id>` to read what's done in it.
2. Write for people who use the product, not developers. Lead with the best change.
3. Keep it under 4 short lines.
4. Hand it to the person in your report: they save and approve it on the project's Releases page before it's used.

# Check before handing over
- No internal ticket keys or code names
- Matches the product's voice (see project memory)
